# AIRTI GitHub 视觉资产设计规格

**日期**：2026-08-13  
**状态**：已完成方案确认，待生成实现  
**应用范围**：GitHub 仓库 README 与项目头像候选素材

## 1. 目标

为 AIRTI 全人蛋白组反向钓靶项目制作两张风格统一的位图资产：项目图标和完整流程示意图。图片本身不包含文字、字母、数字、标签、图例或水印；视觉含义、流程顺序与证据边界全部由 README 中紧邻图片的中文图注说明。

视觉资产用于帮助访问者快速理解项目主题和计算链路，不代替方法说明、运行状态或验证报告。

## 2. 统一视觉语言

- 风格：深色科研科技感，精细但克制的三维生物信息学可视化；
- 主色：深海军蓝与近黑背景，青色、蓝色和紫色发光结构；
- 核心意象：小分子、蛋白口袋、全蛋白组结构网络、AI 计算节点、分子动力学轨迹和候选收敛；
- 构图：光流与空间位置表达方向，不依赖文字、序号或符号标签；
- 一致性：两张图采用相同材质、光照、色彩与视觉密度；
- 禁止项：任何可读或疑似可读字符、品牌标识、实验室名称、软件名称、水印、界面控件、伪图表刻度和装饰性乱码。

图像只表达“计算候选逐步收敛”的概念，不以奖章、对勾、确定性靶心或类似意象暗示靶点已经被实验确认。

## 3. 项目图标

### 3.1 文件与用途

- 目标文件：`docs/assets/airti-icon.png`；
- 画幅：正方形，适应 GitHub README 顶部展示，也可作为仓库头像候选；
- 构图要求：主体居中，四周保留安全边距，在缩小到 64–128 px 时仍能识别。

### 3.2 视觉构成

中央为一个青蓝发光的小分子，正进入或贴合一个抽象的紫蓝色蛋白结合口袋。外围由稀疏神经网络节点和一条环形粒子轨迹包围，分别隐喻 AI 评估与动态复核。口袋形态应自然、不封闭，形成“由分子反向寻找蛋白作用位点”的视觉方向。

背景采用完整深色底，不要求透明通道。图标不使用字母缩写或项目名称。

## 4. 完整流程示意图

### 4.1 文件与用途

- 目标文件：`docs/assets/airti-workflow.png`；
- 画幅：横向宽幅，适合 GitHub README 页面宽度；
- 阅读方向：从左向右；
- 构图要求：各阶段连续但边界可辨，缩放后仍能看出从大规模空间到少量候选的收敛关系。

### 4.2 无文字流程语义

流程图按以下空间顺序组织：

1. 左侧以一至五个形态不同的小分子表示查询输入；
2. 分子进入由大量不同蛋白轮廓和口袋构成的人源蛋白结构网络；
3. 多束对接构象进入发光口袋，形成大规模结构筛选阶段；
4. 候选收敛到神经网络状计算核心，并形成少量高质量蛋白–配体复合物；
5. 复合物进入带有时间感的环形轨迹、溶剂粒子与构象波动，表示分子动力学复核；
6. 右侧输出少量分层排列的候选复合物，并以独立的实验器皿或检测波纹作为后续实验验证入口。

阶段间使用连续光流、粒子束或细箭头表达方向。右侧实验意象必须与计算输出保持视觉间隔，避免暗示实验已经包含在当前计算流程中。

## 5. README 布局与图注

README 顶部标题下居中展示项目图标，并提供简短图注，解释中央小分子、蛋白口袋、神经网络节点和动态轨迹分别代表查询分子、反向靶点匹配、AI 精评与动力学复核。

在项目简介和证据边界之后展示流程图。图注按从左到右的顺序说明：1–5 个查询分子进入人源 canonical 蛋白结构与口袋库，经背景校准的多种子对接、Boltz-2 多种子精评和 GROMACS 分子动力学复核，最终形成可追溯候选排序，并将候选交给独立湿实验验证。

图注必须明确：图示是目标生产流程，不代表当前已经实现全人蛋白组 ready 覆盖、完成 100 ns MD 或获得实验靶点确认；实际通过范围以 README“当前阶段”和验证报告为准。

Markdown 图片应使用有意义的替代文本，以保证图片无法加载或使用辅助技术时仍能理解内容。图注不写入图片像素。

## 6. 生成与质量检查

使用内置 ImageGen 分别生成两个独立资产，不以同一画布裁切替代。生成后逐张检查：

- 是否完全没有可读文字、字母、数字、水印或伪标签；
- 图标缩略后主体是否清晰、边缘是否完整；
- 流程图是否具备明确的左到右顺序和逐级收敛关系；
- 两张图是否具有一致的色彩、光照和材质；
- 是否存在把计算候选误导为实验确认的视觉符号；
- PNG 文件能否正常解码，尺寸与纵横比是否符合用途；
- README 相对路径、替代文本和图注是否正确渲染。

若首轮图像出现字符或顺序含混，只针对问题资产进行一次定向迭代。最终仅保留被 README 引用的版本；原始生成文件不作为运行工件或科学证据。

## 7. GitHub 更新范围

本次变更只包括：两张 PNG 资产、README 图片与图注，以及本设计规格。不修改算法、参考库、容器、模型、运行参数或既有验证结论。

变更将在当前 `codex/airti-production-readiness` 分支提交并推送。推送前检查工作树范围、图片文件、Markdown 链接和现有测试；如已有该分支的 Pull Request，则更新原 PR，不创建重复 PR。
